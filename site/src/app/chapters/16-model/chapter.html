As estrelas são um componente próprio, que dá para usar em qualquer lugar. O detalhe novo: a nota é de quem usa o componente, mas o componente também pode mudá-la. Ao final do capítulo, você vai saber fazer esse vaivém com model().

Num documento compartilhado na nuvem, você e um colega editam o mesmo texto. O que um escreve aparece para o outro, e vice-versa. Não há "o meu" e "o seu": há um texto só, sincronizado.

O model() é isso entre um componente pai e um filho: um valor que os dois podem mudar, e que fica sempre igual dos dois lados.

Input e output num só

No capítulo 15, o input só descia e o output só subia. Um model faz os dois: é um input que o próprio filho pode mudar com set, e cada mudança avisa o pai.

A "banana na caixa": [( )]

No pai, os colchetes e os parênteses juntos, [(rating)], fazem o two-way binding, o binding nos dois sentidos. O apelido "banana na caixa" ajuda a lembrar a ordem: os parênteses (a banana) ficam dentro dos colchetes (a caixa). Ele é só um atalho:

Com o atalho, você passa o signal sem parênteses: [(rating)]="rating". O Angular precisa do signal em si, para poder tanto ler quanto mudar o valor dele.

Quando usar model e quando usar input e output

Use model() em componentes de controle, que existem para editar um valor: estrelas, um seletor de cor, um campo de busca próprio. Para o resto, prefira input() e output(): deixam claro que só o pai muda os dados, e o fluxo fica mais fácil de seguir.

Você escreveu [(rating)]="rating()". Com os parênteses, o Angular recebe só o número, e não tem onde gravar o valor novo que vem do filho. Como sair: passe o signal sem chamar: [(rating)]="rating".

O filho declarou rating = input(0) e tentou rating.set(...). Um input só é lido pelo filho. Junto vem outro erro, NG8007, dizendo que as duas metades do [(rating)] não estão ligadas ao mesmo alvo: não existe o evento ratingChange. Como sair: declare com model(0).
