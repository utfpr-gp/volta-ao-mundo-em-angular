É o momento em que o app deixa de ser uma página estática e vira um app de dados. Ao final do capítulo, você vai saber transformar qualquer array num pedaço de tela com @for, e entender o papel do track.

Para um evento com 300 pessoas, a gráfica não desenha 300 crachás à mão: faz um modelo e imprime um para cada nome da lista. Se chegar uma pessoa nova, imprime só o crachá dela, e não os 300 de novo.

O @for é o modelo do crachá: um bloco de template repetido para cada item do array. E o track é o que permite à gráfica saber de quem é cada crachá, para refazer só o que mudou.

O @for

Leia a primeira linha assim: "para cada country do array visible(), identificado pelo country.code, repita este bloco". Dentro do bloco, country é o item da vez, como o c das arrow functions do . O @empty é opcional e aparece quando o array está vazio.

O let i = $index dá um nome à posição do item, começando em zero; por isso a tela mostra {{ i + 1 }}. Além do $index, o @for oferece $count (o total), $first, $last, $even e $odd.

A classe: um array num signal

Repare em três coisas. O array está num signal, com o tipo Country[]. A lista visível é um computed que usa o filter do capítulo 3. E o remove não altera o array: cria um novo, sem o país, com update e filter. Trocar o array inteiro é o que avisa o signal de que algo mudou. Os botões de filtro usam [class.active], um property binding que liga uma classe CSS quando a condição é verdadeira.

Por que o track é obrigatório

Quando o array muda, o Angular precisa decidir o que fazer com cada elemento da página: manter, mover, reescrever, criar ou remover. O track diz qual valor identifica cada item. Com uma identidade estável, como o código do país, o Angular reconhece "este é o Brasil de antes" e só mexe no que realmente mudou. Compare:

Com track country.code, adicionar um país no começo cria um único nó. Com track $index, o Angular acha que o item da posição 0 "mudou de conteúdo", e reescreve todos. Numa lista de seis países, você não percebe; numa de mil, com imagens e campos, a diferença aparece. Use sempre um identificador único do item, geralmente um id ou um código.

No @for, o track é obrigatório. Como sair: acrescente ; track com o identificador do item, como em @for (country of countries(); track country.code). Se os itens não tiverem identificador nenhum, como uma lista de textos, use track $index.

Você escreveu @for (country of visible; ...). O signal não é o array: é a caixinha com o array dentro. O TypeScript reclama que não sabe percorrer aquilo. Como sair: visible().
