Até aqui, o Passaporte conhecia seis países, escritos à mão num arquivo. Neste capítulo, ele busca os 195 numa API, com nome, capital e população, e passa a guardar o que você marca num servidor que roda no seu computador: feche o navegador, abra de novo, e os carimbos continuam lá.

Ao final do capítulo, você vai saber buscar e enviar dados com o HttpClient, mostrar na tela que algo está carregando ou deu errado, e rodar um servidor de mentirinha com o json-server.

Quem manda uma carta não fica parado na frente da caixa de correio. Põe a carta, volta para a vida, e trata da resposta quando ela chega: pode ser a resposta esperada, pode ser um "destinatário desconhecido", e pode não chegar nunca.

Uma requisição HTTP é essa carta. O app pede os países à API e continua funcionando; quando a resposta chega, o service a guarda, e a tela acompanha. E, como no correio, o código precisa saber o que fazer quando a resposta é um erro.

Buscar com get

O service pede o HttpClient com inject(), como pedia o Router. No Angular 22, ele já está disponível para o app inteiro: não é preciso configurar nada no app.config.ts.

  • this.http.get<ApiCountry[]>(COUNTRIES_URL) prepara um GET. O tipo entre <> diz ao TypeScript o formato da resposta; ele confia em você, e não confere.
  • {{ '.subscribe({ next, error })' }} faz a requisição sair e diz o que fazer com a resposta: no next, a resposta chegou; no error, algo deu errado.
  • O status é um signal com três valores: 'carregando', 'pronto' e 'erro'. A tela olha para ele e decide o que mostrar.

O get não devolve os países: devolve um Observable, a promessa de um valor que vai chegar. Diferente de uma Promise, um Observable não faz nada sozinho: a requisição só sai quando alguém se inscreve com subscribe. Os Observables são o assunto do , e o mostra como transformar um deles em signal.

Salvar com put no json-server

Os países vêm da API do livro, que só lê. O que é seu, os países visitados e as anotações, precisa de um lugar que aceite escrita. O json-server cria uma API de verdade a partir de um arquivo JSON, no seu computador:

Com ele ligado, GET http://localhost:3000/passport devolve o objeto passport, e um PUT no mesmo endereço troca o objeto inteiro e grava no db.json. É isso que o save() do service faz a cada mudança.

Repare que o service continua funcionando se o json-server estiver desligado: o que você marca fica na memória, e um aviso no topo da tela conta que não está sendo salvo.

Até pouco tempo atrás, o HttpClient só existia depois do provideHttpClient(), e o withFetch() trocava o mecanismo antigo do navegador pelo fetch. No Angular 22, o HttpClient já está disponível, e o fetch já é o padrão. O provideHttpClient() continua existindo para configurar o cliente, como no , com os interceptors.

Durante anos, os tutoriais usaram a REST Countries, uma API gratuita e aberta. Quando este capítulo foi escrito, a versão que todos usavam já tinha sido desativada, e a nova pedia cadastro e uma chave secreta. Num app que roda no navegador, a chave fica visível para quem abrir o código, e não serve para um projeto de estudo.

É a lição mais importante sobre APIs de terceiros: elas mudam, e o seu app depende delas. Antes de adotar uma, veja quem a mantém, se há limite de uso, se pede chave, e tenha um plano para quando ela mudar.

Sem ninguém inscrito, o Observable não faz a requisição. Não há erro: só não acontece nada. Como sair: o .subscribe(...), com o que fazer na resposta.

Por segurança, o navegador só entrega a resposta de outro endereço se o servidor disser que aceita, com o cabeçalho Access-Control-Allow-Origin. Isso se chama CORS. A API do livro e o json-server dizem que aceitam; muitos sites, não. Como sair: o problema é do servidor, e não do seu código. Use uma API feita para ser chamada do navegador.

O pais.json, em vez de paises.json, não existe, e o servidor responde 404. Graças ao error, a tela mostra "Não foi possível carregar os países". Como sair: abra o endereço no navegador; se ele não abrir lá, não vai abrir no app.

O saveNote salva a cada letra digitada. Funciona, mas é desperdício: o servidor recebe trinta pedidos para guardar uma frase. Como sair: esperar a pessoa parar de digitar antes de salvar. É exatamente o que o debounceTime do RxJS faz, no próximo capítulo.
