Antes: cada clique pedia uma página inteira

Pense no site de uma universidade há uns quinze anos. Você clicava num link, o navegador mandava um pedido ao servidor (o computador, em algum lugar da internet, que guarda o site) e ficava esperando. O servidor respondia com uma página HTML completa: cabeçalho, menu, conteúdo e rodapé. O navegador apagava tudo e desenhava de novo, até o que não tinha mudado. A tela piscava, e o cabeçalho viajava pela rede a cada clique.

Hoje: a página carrega uma vez, e o clique pede só os dados

Numa aplicação moderna, a página inteira chega uma vez só, no primeiro acesso. Depois, cada clique pede ao servidor apenas os dados que faltam. Esse tipo de aplicação se chama SPA, aplicação de página única. O Gmail, o Google Maps e o próprio site que você está lendo funcionam assim.

Biblioteca ou framework: quem chama quem?

🧰 Biblioteca

seu código → biblioteca

Você chama a biblioteca quando precisa. Exemplo: o date-fns, que só formata datas.

🏭 Framework

framework → seu código

O framework é a estrutura e chama o seu código na hora certa. Você escreve as peças; ele monta.

Você já viu isso acontecer em pequeno. Quando escreve botao.addEventListener('click', somar), quem chama a função somar é o navegador, na hora do clique, e não você. O framework faz o mesmo com o app inteiro: ele chama o seu código quando a tela precisa ser montada ou atualizada.

O React se apresenta como uma biblioteca de interface. O Angular é um framework completo. Essa diferença explica quase tudo o que vem a seguir.

Angular, em uma frase

O Angular é um framework de código aberto, mantido pelo Google, para construir aplicações web de página única em TypeScript.

Dois pedaços dessa frase são novos. Código aberto quer dizer que o código é público: qualquer pessoa pode ler, usar e contribuir. E o TypeScript é o JavaScript com tipos: os tipos fazem o editor apontar erros enquanto você escreve, antes de o código rodar. Ele tem um capítulo só dele, o .

Por que aprender Angular

Juntando tudo: TypeScript desde a primeira linha, ferramentas oficiais que evoluem juntas e projetos com a mesma estrutura, o que ajuda muito quem trabalha em equipe e quem chega num projeto que já existe.

O Angular tem um ritmo previsível. A partir da versão 22, sai uma versão nova por ano, e cada uma tem 24 meses de suporte: 12 de suporte ativo, com melhorias e correções, e 12 de suporte de longo prazo, só com correções críticas e de segurança. Até a versão 21, saía uma versão a cada seis meses.

Do AngularJS ao Angular de hoje

Um pouco de história, porque ela explica muita confusão nos tutoriais que você vai encontrar. Não precisa decorar nada: o que importa é saber que existe um "antes" e um "agora".

Tudo o que você vai estudar neste livro é do Angular moderno: os marcos destacados, de 2022 em diante.

O Angular transforma os templates dos componentes em instruções JavaScript que criam e atualizam a tela. Quem faz isso é o compilador, e o motor que executa essas instruções se chama Ivy, padrão desde a versão 9. Com ele, os apps ficaram menores e mais rápidos de compilar.

Por muitos anos, o Angular descobria "quando" atualizar a tela com uma biblioteca chamada Zone.js: ela observava todo clique, temporizador e requisição e, depois de cada um, mandava o Angular conferir a árvore inteira de componentes. Funcionava, mas conferia muito mais do que precisava.

Com os signals, o Angular passou a saber exatamente qual valor mudou e onde ele aparece. Por isso, a partir da versão 21, projetos novos são criados sem o Zone.js, ou seja, zoneless. E, desde a versão 22, cada componente só é conferido quando algo dele muda: a estratégia chamada OnPush virou o padrão. Você vai ver signals de perto no .

Neste capítulo, a mão no código é de leitura: o mesmo componente, um botão que conta cliques, escrito nos quatro. Não se preocupe em entender cada linha agora. Repare no estilo de cada um, e na linha destacada, que é onde cada um guarda o estado (o número de cliques).

O Angular separa a classe, em TypeScript, do template, que é o HTML. Aqui o template está dentro do arquivo .ts, entre crases, só para caber num exemplo curto; em projetos de verdade ele costuma ficar num arquivo .html separado, ao lado. O @Component liga os dois. O estado é um signal, e o template lê o valor chamando total().

O React escreve o HTML dentro do JavaScript, numa sintaxe chamada JSX. O componente é uma função, e o estado vem do hook useState.

O Vue põe script e template no mesmo arquivo .vue. O estado é um ref, e no template você usa o valor direto.

O Svelte também junta script e HTML, e marca o estado com a rune $state. Antes de rodar, o compilador transforma tudo em JavaScript enxuto.

Agora é a sua vez: mexa num Angular de verdade

Sem instalar nada, você pode ver o Angular atualizando a tela sozinho:

  1. Abra o playground do Angular.
  2. O editor mostra o código de um componente. Procure o trecho entre crases, depois de template:: é o HTML. Ache ali um texto que aparece na área de visualização, como um título, e troque por outro.
  3. Olhe para a área de visualização: o texto novo aparece em poucos segundos, sem você recarregar a página.

O que muda na tela: só o texto que você trocou. Quem refez a visualização foi o playground, que recompila o app a cada mudança no código; no seu computador, o ng serve fará o mesmo ().
