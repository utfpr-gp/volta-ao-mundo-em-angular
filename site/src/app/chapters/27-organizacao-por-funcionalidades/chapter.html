A pasta src/app do Passaporte já tem mais de vinte pastas lado a lado: cabeçalho, cartões, abas, pipe, páginas. Achar alguma coisa virou garimpo. Neste capítulo, nada muda na tela: o que muda é onde cada arquivo mora.

Ao final do capítulo, você vai saber separar o projeto em core, shared e features, e seguir a regra que impede o projeto de virar um nó: uma funcionalidade não importa outra.

Numa casa, cada cômodo tem as suas coisas: as panelas ficam na cozinha, a toalha no banheiro. O que é da casa toda, como o quadro de luz e a caixa d'água, fica num lugar só. E o que todo mundo usa, como a tesoura e a fita adesiva, mora numa gaveta comum, e não emprestado de um quarto.

No projeto, cada feature é um cômodo: as peças de uma funcionalidade ficam juntas. O core é o quadro de luz: o que o app tem uma vez só. O shared é a gaveta comum: peças genéricas, que qualquer cômodo pode usar.

A regra: uma feature não importa outra

  • Uma feature pode importar do core, do shared e dela mesma.
  • Uma feature nunca importa de outra feature.
  • O shared não importa de core nem de features: ele não sabe que o app existe.

O motivo da regra: se a página do país importasse o cartão da lista, mudar o cartão poderia quebrar a página do país, e apagar a lista, um dia, arrastaria a outra junto. Com a regra, cada feature pode mudar, crescer ou sumir sem mexer nas outras. E o lazy loading agradece: cada feature vira um chunk limpo.

E quando duas features precisam da mesma peça? Ela sobe: se é genérica, para o shared; se é do app, para o core. Foi o que aconteceu com o countries.ts, que a lista e a página do país leem.

O que muda na tela: nada. O Passaporte continua igual, e os testes continuam passando. A mudança é para quem lê o código.

O Angular não reclama: o import é válido. O problema aparece meses depois, quando alguém muda o cartão da lista e a página do país quebra. Como sair: se duas features precisam da peça, ela sobe para o shared ou para o core.

Um mv no terminal muda o arquivo de lugar, mas não corrige quem o importa. Como sair: mova pelo VS Code, que atualiza os imports, ou corrija os caminhos que o build apontar.

Um componente que recebe um Country já não é genérico: ele só serve para países. Como sair: se ele é do assunto do app, o lugar é uma feature; se é genérico de verdade, ele recebe dados simples, como o Panel, que recebe só conteúdo projetado.
