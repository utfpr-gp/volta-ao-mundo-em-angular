O Passaporte tem cores espalhadas por todo canto: bg-slate-900 no cabeçalho, #12263a no placar, #d99a1e no destaque. Neste capítulo, essas cores ganham nomes, viram design tokens, e o app ganha de presente o modo escuro, sem mudar nenhum componente para isso.

As duas imagens são o mesmo app. O que mudou foi só o valor dos tokens. Ao final do capítulo, você vai saber criar os tokens do seu app e entender por que os nomes deles são a parte mais importante.

Numa empresa, você não escreve no documento "fale com a Ana"; escreve "fale com a coordenação". Se a Ana sair, o documento continua certo: basta outra pessoa assumir a coordenação.

Um design token é o nome do cargo. Em vez de pintar o cabeçalho de "azul-marinho", você pinta de primary, a cor principal do app. No modo escuro, outro tom assume o cargo de primary, e todo lugar que usa o token acompanha.

Tokens no Tailwind: o @theme

No Tailwind 4, os design tokens são declarados no CSS global, dentro de um bloco @theme. Cada token é uma variável CSS com um prefixo que diz o tipo: --color- para cores, --radius- para arredondamentos, --font- para fontes.

O Tailwind lê o @theme e cria classes para cada token: --color-primary vira bg-primary, text-primary, border-primary; --radius-card vira rounded-card. E, no CSS dos componentes, você usa o token direto, com var(--color-primary).

Nomes de papel, nunca de aparência

Repare nos nomes: primary, surface (a superfície de fundo), card, ink (a tinta do texto), highlight (o destaque). Nenhum se chama "azul" ou "creme". O motivo aparece no modo escuro: lá, a surface fica azul-escura e a ink fica clara. Um token chamado --color-white que vale azul-escuro seria uma armadilha para quem lê o código.

O modo escuro com um bloco de CSS

O @media (prefers-color-scheme: dark) vale quando o sistema de quem usa está no modo escuro. Dentro dele, os mesmos tokens recebem outros valores. Como todo componente usa os tokens, todo o app troca de tema de uma vez. Nenhuma linha de TypeScript foi necessária.

Um cuidado: no modo escuro, o contraste entre texto e fundo continua importante. O texto precisa ser bem legível nos dois modos; o mostra como conferir.

Seguir o sistema é o comportamento mais simples e mais respeitoso. Se quiser um botão para a pessoa escolher, o caminho é guardar a escolha num signal, escrever um atributo como data-theme="dark" no <html> e trocar os tokens por esse atributo, em vez da preferência do sistema. O que muda na tela: o Passaporte inteiro troca para o tema escuro da missão.

Você declarou --color-brand num :root comum e tentou usar bg-brand. A variável existe, mas o Tailwind só cria classes para o que está no @theme. Num template, a classe simplesmente não faz nada; num @apply, o build reclama. Como sair: declare o token dentro do @theme.

Um bg-white ou #ffffff que ficou para trás não muda com o tema, e o cartão fica branco no meio do app escuro. Como sair: procure as cores soltas no projeto (no VS Code, Ctrl + Shift + F e busque por # e por nomes como white) e troque por tokens.

Um token chamado pela aparência mente assim que o tema muda. Como sair: nomeie pelo papel: primary, surface, ink, danger.
