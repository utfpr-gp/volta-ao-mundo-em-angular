Construir uma casa do zero exige fundação, encanamento e fiação antes da primeira parede bonita. Uma boa construtora entrega tudo isso pronto, no padrão, e você começa direto pela parte que importa: os cômodos do seu jeito.

O Angular CLI é essa construtora. Um comando cria o projeto inteiro, com a estrutura que todo projeto Angular segue, e outros comandos ligam o app, criam peças novas, rodam os testes e preparam a versão final.

O comando ng

O Angular CLI é um programa de terminal; o comando dele se chama ng. Os que você mais vai usar:

Como o app liga

O caminho que o simulador mostrou acontece toda vez que alguém abre o app. Ele é a SPA do na prática: o navegador recebe uma única página, o index.html, quase vazia, com um elemento <app-root>. O main.ts manda o Angular ligar o app a partir do componente App, e o Angular desenha o template dele dentro do <app-root>. Tudo o que você construir daqui em diante vai aparecer ali dentro.

O ng serve e a recarga automática

O ng serve monta o app e o deixa disponível só no seu computador, num endereço como http://localhost:4200/. localhost quer dizer "este computador", e 4200 é a porta, uma espécie de número de apartamento no prédio que é o seu computador. Esta é a saída real:

Repare em Watch mode enabled: o CLI fica de olho nos arquivos. A cada vez que você salva um arquivo, ele monta o app de novo e o navegador recarrega sozinho. O terminal fica ocupado enquanto o servidor roda; para desligar, aperte Ctrl + C.

Para montar o app, o CLI usa ferramentas especializadas: o compilador do Angular transforma os templates em JavaScript, e o esbuild junta e enxuga todos os arquivos num pacote pequeno, chamado bundle. Os testes rodam com o Vitest. O CLI esconde essa complexidade: você só usa ng serve, ng build e ng test.

"Este comando não está disponível fora de um workspace", ou seja, fora da pasta de um projeto Angular. Você abriu o terminal e rodou ng serve sem entrar na pasta do projeto. Como sair: entre na pasta com cd passaporte (confira com pwd) e rode de novo.
