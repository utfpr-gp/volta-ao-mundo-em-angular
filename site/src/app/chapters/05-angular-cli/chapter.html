Construir uma casa do zero exige fundação, encanamento e fiação antes da primeira parede bonita. Uma boa construtora entrega tudo isso pronto, no padrão, e você começa direto pela parte que importa: os cômodos do seu jeito.

O Angular CLI é essa construtora. Um comando cria o projeto inteiro, com a estrutura que todo projeto Angular segue, e outros comandos ligam o app, criam peças novas, rodam os testes e preparam a versão final.

Como o app liga

O caminho que o simulador mostrou acontece toda vez que alguém abre o app. Ele é a SPA do na prática: o navegador recebe uma única página, o index.html, quase vazia, com um elemento <app-root>. O main.ts manda o Angular ligar o app a partir do componente App, e o Angular desenha o template dele dentro do <app-root>. Tudo o que você construir daqui em diante vai aparecer ali dentro.

O ng serve e a recarga automática

O ng serve monta o app e o deixa disponível só no seu computador, num endereço como http://localhost:4200/. localhost quer dizer "este computador", e 4200 é a porta, uma espécie de número de apartamento no prédio que é o seu computador. Esta é a saída real:

Repare em Watch mode enabled: o CLI fica de olho nos arquivos. A cada vez que você salva um arquivo, ele monta o app de novo e o navegador se atualiza sozinho. O terminal fica ocupado enquanto o servidor roda: para continuar digitando comandos, abra um segundo terminal. Para desligar o servidor, aperte Ctrl + C no terminal dele. (No terminal, Ctrl + C não copia: ele interrompe o programa que está rodando.)

Para montar o app, o CLI usa ferramentas especializadas: o compilador do Angular transforma os templates em JavaScript, o esbuild junta e enxuga todos os arquivos num pacote pequeno, chamado bundle, e, no ng serve, o Vite entrega esse resultado ao navegador (o ➜ Local: da saída é dele). Quando você muda um template ou um CSS, a tela se atualiza sem recarregar a página inteira. Os testes rodam com o Vitest. O CLI esconde essa complexidade: você só usa ng serve, ng build e ng test.

O ng new faz algumas perguntas antes de criar. Responda assim:

  1. Na primeira vez que você usa o CLI, ele pergunta se quer compartilhar dados de uso anônimos com o time do Angular (Would you like to share pseudonymous usage data…). Responda como preferir: N está ótimo.
  2. Em Which stylesheet system would you like to use?, escolha CSS.
  3. Em Do you want to enable Server-Side Rendering (SSR)…, responda N (não).
  4. Na pergunta sobre ferramentas de IA, não marque nenhuma e confirme.

Nas listas, use as setas para escolher e Enter para confirmar; nas perguntas com (y/N), digite y para sim ou N para não. Depois ele baixa os pacotes, o que pode levar alguns minutos na primeira vez, e o cd passaporte entra na pasta nova.

"Este comando não está disponível fora de um workspace", ou seja, fora da pasta de um projeto Angular. Você abriu o terminal e rodou ng serve sem entrar na pasta do projeto. Como sair: entre na pasta com cd passaporte (confira com pwd) e rode de novo.

Como sair: no PowerShell, rode o comando abaixo, confirme com S e abra um terminal novo. Ele libera scripts só para o seu usuário.

É o mesmo erro do node que você viu no : o Angular CLI não foi instalado, ou o terminal foi aberto antes da instalação. Como sair: rode o npm install -g @angular/cli@22 e abra um terminal novo.

Toda mensagem de erro tem três partes: quem reclamou, o problema e, muitas vezes, uma dica. Em Port 4200 is already in use. Use '--port' to specify a different port., quem reclamou é o Angular CLI, o problema é a porta ocupada e a dica é o --port.

Leia a primeira e a última linha antes de tudo. Procure nome de arquivo e número de linha, como app.ts:12. E, para buscar ajuda na internet, copie a mensagem exata, entre aspas. Você vai treinar isso muitas vezes; o é todo sobre mensagens de erro.
