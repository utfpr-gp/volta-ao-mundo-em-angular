No capítulo anterior, o Passaporte era um cartão só, dentro do componente App. Agora ele ganha cara de app: um cabeçalho com menu, uma lista de países e um rodapé.

O mais importante não aparece na imagem: cada uma dessas três partes é um componente separado, criado com o Angular CLI, com o seu próprio HTML, CSS e TypeScript. Ao final deste capítulo, você vai saber olhar para qualquer tela e enxergar as peças dela, e montar o Passaporte com elas.

Na química, tudo é feito de átomos. Átomos se juntam em moléculas, e moléculas formam organismos inteiros. Um átomo de oxigênio sozinho não faz muita coisa; junto com dois de hidrogênio, vira água.

O designer Brad Frost percebeu que as telas funcionam do mesmo jeito e chamou a ideia de Atomic Design. Uma bandeira é um átomo. Bandeira, nome e capital juntos formam uma molécula: o cartão de um país. Vários cartões formam um organismo: a lista de países. E a tela inteira é a soma dos organismos.

O que é um componente, de novo

Você viu no que um componente é um pedaço da tela com três partes: a aparência (o template, em HTML), o estilo (o CSS) e o comportamento (a classe, em TypeScript). No Angular, cada parte costuma ficar num arquivo, e os três ficam juntos numa pasta com o nome do componente.

Os cinco níveis do Atomic Design

O Atomic Design tem cinco níveis. Os três primeiros vêm da química; os dois últimos falam da tela pronta:

  1. Átomos: as peças que não dá para dividir mais, como uma bandeira, um nome, um botão, um link.
  2. Moléculas: átomos juntos com um propósito, como o cartão de um país ou um campo de busca com o botão.
  3. Organismos: partes inteiras da tela, como o cabeçalho, a lista de países e o rodapé.
  4. Template: o esqueleto da tela, com os organismos no lugar, mas ainda sem os dados.
  5. Página: o template com os dados de verdade. É o que a pessoa vê.

Nem todo átomo precisa virar um componente Angular: uma bandeira pode ser só um <span>. O Atomic Design é um jeito de pensar a tela; você decide quais peças valem um componente. Neste capítulo, os três organismos viram componentes: Header, CountryList e Footer.

Como um componente usa outro

Todo componente tem um selector: o nome da tag que o representa no HTML.

Para usar o Header dentro do App, são dois passos: importar a classe no imports do App, e escrever a tag <app-header /> no template dele.

Cada tag vira o componente inteiro, com o HTML e o CSS dele. É assim que a árvore de componentes do capítulo 1 sai do papel: o App é a raiz, e o Header, a CountryList e o Footer são os filhos.

Cada componente com o seu estilo

O CSS de um componente só vale para ele. A classe .card do country-list.css não afeta nenhum outro componente, mesmo que outro também tenha uma classe .card. Isso deixa você escrever nomes curtos sem medo de conflito. O que vale para o app inteiro, como a fonte, fica no src/styles.css. Você vê estilos com calma no .

Quando criar um componente novo?

  • Ele se repete? O cartão de país aparece várias vezes: forte candidato.
  • Ele tem um nome? Se você chama a parte de "o cabeçalho", ela provavelmente é um componente.
  • O arquivo cresceu demais? Um template enorme fica mais fácil de entender dividido em partes.

Até a versão 14, todo componente precisava ser declarado num NgModule, uma espécie de caixa que agrupava componentes. Era mais uma peça para entender e manter. Os componentes standalone, padrão desde a versão 19, dispensam essa caixa: cada componente diz, no próprio imports, o que usa.

É por isso que os componentes que o CLI gera hoje não têm standalone: true escrito: standalone já é o padrão. Se você encontrar NgModule num tutorial, ele é de um Angular mais antigo.

Você escreveu <app-header /> no template, mas esqueceu de pôr Header no imports do componente. Para o Angular, app-header é uma tag desconhecida. Como sair: acrescente a classe ao imports (e o import no topo do arquivo), ou corrija o nome da tag para bater com o selector.
