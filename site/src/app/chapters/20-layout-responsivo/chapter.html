Até aqui, o Passaporte era uma pilha: um bloco embaixo do outro, em qualquer tela. No celular, ótimo; no computador, uma faixa estreita com muito espaço sobrando. Neste capítulo, o Passaporte aprende a se reorganizar conforme a largura da tela.

É o mesmo código nas duas imagens. Ao final do capítulo, você vai saber montar um layout pensando primeiro no celular, usar os prefixos do Tailwind para mudar o que precisa nas telas maiores e transformar o menu num botão.

Quem arruma primeiro a mala de mão escolhe o essencial, porque não cabe muita coisa. Se depois a viagem ganhar uma mala grande, é só acrescentar: o essencial já está lá. O caminho contrário é sofrido: arrumar a mala grande e depois tentar espremer tudo na pequena. Sempre sobra alguma coisa para fora.

O celular é a mala de mão. Desenhar mobile-first é montar primeiro a tela pequena, com o essencial, e depois acrescentar o que muda quando a tela cresce: mais colunas, links à vista, a bandeira ao lado do texto.

Sem prefixo é o celular

No Tailwind, uma classe sem prefixo vale para todas as larguras, a partir da menor. Os prefixos sm:, md:, lg: e xl: são os breakpoints: a classe com prefixo passa a valer quando a tela alcança aquela largura, e continua valendo daí para cima.

PrefixoVale a partir deTelas típicas
(nenhum)0 pxtodas, começando pelo celular
sm:640 pxcelular deitado
md:768 pxtablet
lg:1024 pxnotebook
xl:1280 pxmonitor

Então grid md:grid-cols-2 se lê assim: "uma grade; a partir de 768 px, com duas colunas". Esse jeito de ler é o mobile-first: o celular é o ponto de partida, e cada prefixo é uma mudança para as telas maiores.

Grid para a página, flexbox para a linha

O layout do Passaporte agora mora no componente raiz:

Leia as classes do <main> em partes:

  • mx-auto max-w-6xl: no máximo 1152 px de largura, centralizado. Num monitor grande, o conteúdo não se espalha até as bordas.
  • p-4 sm:p-6: espaço interno de 16 px no celular, de 24 px a partir de 640 px.
  • grid gap-6: uma grade, com 24 px entre os blocos. Sem colunas declaradas, é uma coluna só.
  • md:grid-cols-[minmax(0,2fr)_minmax(0,3fr)]: a partir de 768 px, duas colunas, na proporção 2 para 3. Os colchetes deixam escrever um valor que o Tailwind não tem pronto; o _ faz o papel do espaço.

O placar e o destaque ficam juntos num <aside> (um conteúdo de apoio, ao lado do principal), com flex flex-col gap-6: um embaixo do outro, com espaço entre eles. A regra prática: grid para a página, que tem linhas e colunas; flexbox para enfileirar coisas numa direção só, como os itens de um cartão.

O menu que vira botão

No celular, não cabem os links do cabeçalho ao lado do nome do app. A solução comum é um botão que abre o menu. O estado "aberto ou fechado" é um signal, como os do :

Repare nos dois pares de classes. O botão tem md:hidden: aparece no celular e some a partir de 768 px. Os links lado a lado têm hidden md:flex: escondidos no celular, visíveis a partir de 768 px. O menu do celular fica num @if e também tem md:hidden, para não ficar sobrando se alguém abrir o menu e depois alargar a janela.

O aria-expanded conta aos leitores de tela se o menu está aberto, e o aria-controls diz qual elemento o botão controla. Quem não enxerga a tela também precisa saber o que o botão faz.

Media query no CSS do componente

Os prefixos do Tailwind são atalhos para as media queries do CSS. Nos componentes com CSS próprio, você escreve a media query direto, com a mesma lógica mobile-first: o estilo fora dela é o do celular, e o min-width diz a partir de que largura a mudança vale.

O 64rem é a mesma largura do lg:: 64 vezes o tamanho da fonte padrão, de 16 px, dá 1024 px. Usar rem nas media queries faz o layout respeitar quem aumentou a fonte do navegador.

Repare que o país em destaque mora na coluna estreita: entre 768 px e 1023 px, a tela é larga, mas o cartão é estreito. As media queries só sabem a largura da tela. As container queries perguntam a largura do elemento pai, e o Tailwind 4 já as traz:

Para um componente que pode aparecer em lugares de larguras diferentes, como um cartão reaproveitado, é o caminho mais robusto. Para o layout da página, as media queries continuam sendo o natural.

Com sm:grid-cols-2 md:grid-cols-1, a lista tem duas colunas quando ocupa a tela inteira, entre 640 px e 767 px, e volta a uma quando passa a dividir a tela com o placar.

No Chrome, abra as ferramentas com F12 e aperte Ctrl + Shift + M: a página passa a ser mostrada como num celular, e dá para escolher o aparelho ou arrastar a largura.

O que muda na tela: num celular, tudo numa coluna e o botão "☰ Menu" no cabeçalho; clique nele e os links aparecem. Alargue até passar de 768 px: o botão some, os links aparecem lado a lado, e a lista vai para a direita do placar.

Quem pensa "o md: é o celular" escreve tudo ao contrário. O prefixo diz "a partir deste tamanho", e não "só neste tamanho". Como sair: escreva primeiro as classes do celular, sem prefixo, e depois acrescente com prefixo só o que muda nas telas maiores.

Aconteceu de verdade no Passaporte, antes deste capítulo. Num display: flex, os filhos não encolhem abaixo da largura do próprio conteúdo, e um <input> já nasce com uns 20 caracteres de largura. Como sair: dê min-width: 0 ao filho do flex (no Tailwind, min-w-0), ou empilhe os itens no celular, como fizemos.

Um elemento de 500 px numa tela de 390 px empurra a página para fora da tela. Como sair: deixe o elemento ocupar a largura disponível (w-full) e limite só o máximo (max-w-...).

Sem o <meta name="viewport">, o celular finge ter uma tela de computador e encolhe tudo, e nenhum prefixo funciona como esperado. O Angular CLI já põe essa linha; o problema aparece quando alguém a apaga ou copia um index.html antigo. Como sair: devolva a linha ao <head>.
