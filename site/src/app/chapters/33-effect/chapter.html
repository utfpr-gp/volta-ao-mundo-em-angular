O Passaporte guarda o que você marca no json-server. Mas, se ele estiver desligado, tudo se perde ao recarregar. Neste capítulo, o app passa a guardar uma cópia no próprio navegador, sempre que algo muda, e abre com ela quando o servidor não responde.

A ferramenta é o effect: código que roda sozinho quando um signal muda. Ao final do capítulo, você vai saber usar o effect() para efeitos colaterais, e, tão importante quanto, reconhecer quando um computed é a escolha certa.

Todo viajante cuidadoso tem um hábito: a cada carimbo novo no passaporte, anota no diário de bordo. Ninguém precisa lembrá-lo; a anotação vem junto com o carimbo. E o diário não muda o passaporte: só registra.

O effect é esse hábito. Ele observa signals e, quando eles mudam, faz algo fora do Angular: grava no navegador, manda uma mensagem, mexe no DOM à mão. Já o computed é a conta de quantos carimbos você tem: um valor que vem de outros, sempre certo, sem hábito nenhum.

Gravar no navegador quando o passaporte muda

  • O effect() recebe uma função. O Angular a roda uma vez e anota quais signals ela leu, aqui o saved(). Quando algum deles muda, a função roda de novo.
  • O localStorage é um armário do navegador, que guarda texto por site e continua lá depois de fechar a aba. O JSON.stringify transforma o passaporte em texto, e o JSON.parse, na volta, em objeto.
  • O readCopy() lê a cópia uma vez, ao abrir o app, e o saved passa a valer a cópia enquanto o json-server não responde. Com o try, uma cópia estragada não derruba o app.

Quando o effect roda

O effect não roda no mesmo instante em que o signal muda: ele espera o Angular terminar o que está fazendo. Se o signal mudar três vezes seguidas, o effect roda uma vez, com o último valor. Para gravar no navegador, é ótimo: três gravações seriam desperdício.

Esse atraso é o motivo da regra mais importante do capítulo: se o que você quer é um valor, use computed. Um computed está sempre certo, na hora em que é lido; um signal mantido por um effect fica um passo atrás.

Repare que, até este capítulo, o Passaporte não tinha nenhum effect, e funcionava muito bem. Na maior parte do tempo, computed e métodos bastam; o effect é para a borda, onde o app conversa com o mundo de fora.

O que muda na tela: marque alguns países com o json-server ligado. Pare o npm run api e recarregue: o aviso aparece, e os países continuam marcados. No Chrome, abra as ferramentas com F12, aba Application, e veja a chave passaporte em Local Storage.

Funciona, mas o valor chega um passo atrasado, e quem lê o signal no meio do caminho vê o número velho. Como sair: se é um valor calculado a partir de outros, é computed.

O effect lê visits, escreve em visits, e a escrita o faz rodar de novo, sem fim. Como sair: um effect não deve escrever nos signals que lê. Se precisar mesmo ler um signal sem passar a depender dele, use untracked(() => ...).

Como o toSignal e o resource, o effect precisa saber a quem pertence, para ser destruído na hora certa. Como sair: crie-o no constructor ou num campo da classe.
